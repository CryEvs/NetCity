# Реконструкция БД `main4` (АИС «Сетевой Город. Образование» 5.14.65351.225)

Схема восстановлена по бинарникам и скриптам из этой папки. Подключение к БД для этого не нужно.

Целевая СУБД: **MS SQL Server** (`ns.config` → `NSSqlConnection`, `Initial Catalog=main4`).

## Как это получено

1. **ORM.** `tools/Gen.cs` загружает `FluentNHibernate`-маппинги из DLL системы, строит `NHibernate.Cfg.Configuration` и вызывает `GenerateSchemaCreationScript` для диалекта MsSql2012. Одна таблица (`SCHOOLYEARSUSERS`) замаплена дважды в разном регистре, дубль пропущен.
2. **Сырой SQL.** `tools/IlSql.cs` проходит по IL каждого метода всех сборок `NetCity*`, `IRTech*`, `NS_*` и склеивает строковые литералы (`ldstr`), поэтому запросы, собранные конкатенацией, получаются целиком. Дополнительно разбираются строковые литералы ~3200 ASP-страниц.
3. **Анализ.** `tools/analyze.py` извлекает из запросов таблицы (FROM, JOIN, INTO, UPDATE, DELETE), колонки (списки INSERT, UPDATE SET, `alias.col` с учётом ближайшего объявления алиаса, простые однотабличные запросы), функции, процедуры и представления. Дальше он отсеивает HQL (имена классов), CTE, временные таблицы, табличные переменные и подставляемые в рантайме имена (`join {0} TOT`), а объекты других БД определяет по классу-источнику (`LaDAO`, `KladrDAO`, `StudentsInOut`).

Повторить:
```bash
python db_reverse/tools/analyze.py . db_reverse/tools db_reverse
```

## Развёртывание

```sql
CREATE DATABASE main4 COLLATE Cyrillic_General_CI_AS;
-- затем в контексте main4: 01 -> 02 -> 03 -> 04
```
Проверить скрипты на реальном SQL Server не удалось, на этой машине его нет. Статические проверки пройдены: скобки сбалансированы, дублей объектов нет, все FK ссылаются на существующие таблицы.

**Проверка приложением.** При старте NHibernate запускает `SchemaValidator` (см. `Assemblies/Logs`, `Schema validation failed`). После развёртывания запустите сервисы: в логе будут перечислены все расхождения между БД и маппингами.

## Чего восстановить НЕЛЬЗЯ (важно)

- **Данные.** Нет ни пользователей, ни школ, ни справочников. Без справочных данных (роли и права `ROLES`/`RIGHTS`/`ROLESRIGHTS`, метаданные конструктора отчётов `OBJPROPS`/`QUERIES`/`REPORTS`, `SERVERSETTINGS`, `VERSN` и т.п.) система, скорее всего, не запустится даже при правильной схеме.
- **Тела** хранимых процедур, функций, представлений и триггеров.
- **Индексы**, кроме PK/unique, оригинальные имена ограничений, значения по умолчанию у legacy-таблиц.
- Часть «таблиц» в ORM на самом деле могут быть **представлениями** (например, `EM_SCHOOLS_ALL`). То же касается legacy-таблиц с пометкой «only READ».

## Что рекомендуется сделать параллельно

1. Поискать бэкапы и файлы БД на старом сервере `NET_SCHOOL`: `*.bak`, `*.mdf`/`*.ldf` в `...\MSSQL\DATA`, `...\MSSQL\Backup`, а также теневые копии тома. Для SQL Express файлы часто лежат в `C:\Program Files\Microsoft SQL Server\MSSQL*.SQLEXPRESS\MSSQL\DATA\main4.mdf`.
2. Запросить у разработчика (ИрТех) пустую эталонную БД или скрипты обновления для версии 5.14. Это коммерческий продукт, и эталонная база со справочниками обычно входит в дистрибутив.
3. Использовать эту реконструкцию как карту для проверки и восстановления, если найдётся старый или частичный бэкап.

> ⚠️ В `ns.config` пароли к БД лежат открытым текстом. Если папка куда-то передаётся, их стоит сменить.
