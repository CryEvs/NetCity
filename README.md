# NetCity
NetCity (АИС "Сетевой Город. Образование") - популярная система для образовательных организаций 

# Восстановление БД «Сетевой Город. Образование» 5.14

Набор скриптов и инструментов, который восстанавливает утерянную базу данных `main4` (MS SQL Server) для
АИС «Сетевой Город. Образование» версии **5.14.65351.225**. Схема и справочники получены из скомпилированного кода
системы: исходников и резервной копии БД не было. Здесь же описано, как развернуть систему локально
и какие исправления понадобились, чтобы она заработала на современной Windows.

> ⚠️ **Структура БД восстановлена не полностью.** Работа продолжается: основные сценарии уже проходят,
> но часть таблиц, процедур и представлений пока угадана или отсутствует (см. [Статус](#статус) и
> [Ограничения](#ограничения)). Некоторые разделы системы могут выдавать ошибки.

> **Неофициальный проект.** Он не связан с ООО «ИрТех» и не одобрен им. Если есть возможность получить
> эталонную БД или бэкап у разработчика, лучше сделать это: реконструкция не заменяет оригинал.

Её удобно смотреть через `git diff` между ветками.

## Требования

- Windows с IIS: классический ASP, ASP.NET 4.x, URL Rewrite 2.1
- SQL Server 2016 или новее (проверено на 2025), collation `Cyrillic_General_CI_AS`
- Redis (порт 6379) и MongoDB (порт 27017)
- .NET Framework 4.8
- Установочный каталог системы 5.14.65351.225 (аналог `C:\Program Files\NetCity2`)
- Чтобы перегенерировать скрипты: Python 3, .NET SDK, [`ilspycmd`](https://github.com/icsharpcode/ILSpy)

## Быстрый старт

1. Возьмите ветку реверс-инжиниринга. Если используете свой установочный каталог, скопируйте в его корень `db_reverse/`
   (рядом с `Assemblies`, `Web`, `WebApi` и `ns.config`) и примените [исправления файлов продукта](#исправления-файлов-продукта).
2. Укажите в `ns.config` строку подключения:
   `Data Source=localhost;Initial Catalog=main4;Integrated Security=True;...`
3. Создайте БД. Права администратора Windows не нужны, достаточно роли `sysadmin` в SQL Server.
   **Скрипт удаляет существующую `main4`.**
   ```powershell
   powershell -ExecutionPolicy Bypass -File db_reverse\deploy\rebuild-db.ps1
   ```
4. Настройте IIS, COM-регистрацию, службы и права. Запускать **от администратора**, скрипт можно повторять:
   ```powershell
   powershell -ExecutionPolicy Bypass -File db_reverse\deploy\deploy-admin.ps1
   ```
5. Перезапустите IIS и службы:
   ```powershell
   iisreset; Restart-Service NetCityServices, NetCityQueueProcessor
   ```
6. Откройте `http://localhost:8080` и войдите администратором сервера: логин `_sad_min_`, пароль `servadmin`.
   **Сразу смените пароль.**
7. Дальше всё создаётся штатно, через интерфейс:
   1. адресный справочник (регион → район → населённый пункт);
   2. «Образовательные организации» → «Добавить» (город выбирается в диалоге);
   3. вход администратором школы и мастер ввода данных.

### Что делает `deploy-admin.ps1`

- компоненты IIS, сайт `NetCity` на порту 8080, пулы `NetCity` (классический ASP) и `NetCityApi` (`/webapi`, `/ws`);
- anonymous auth под identity пула, parent paths и кодовая страница 1251 для ASP;
- регистрация COM-сборок (`regasm`), логины пулов в SQL Server (`db_owner`);
- служба `NetCityServices` (токены сессий, .NET Remoting на 127.0.0.1:8458);
- служба `NetCityQueueProcessor`: обёртка `deploy/QueueProcessorHost.cs`, потому что штатный `NetCity.Services.QueueProcessor.exe`
  ждёт `Console.ReadLine()` и под службой сразу завершается. В `ns.config` нужен ключ `<add key="QUEUEPROC" value="manual" />`.

## Как получена схема

1. **ORM.** `tools/Gen.cs` загружает FluentNHibernate-маппинги из сборок системы вместе с соглашениями самого
   приложения (`ReferenceConvention`, `MSSQLConvention`) и генерирует DDL через NHibernate
   (`keep_datetime=true`, поэтому даты имеют тип `DATETIME`). С ключом `--validate` это валидатор схемы с настройками приложения.
2. **Сырой SQL.** `tools/IlSql.cs` проходит по IL всех методов и склеивает строковые литералы, так что запросы, собранные
   конкатенацией, получаются целиком (`tools/il_sql.tsv`). `tools/analyze.py` извлекает из них таблицы и колонки
   и угадывает типы и первичные ключи.
3. **Справочники.** `tools/make_seed.py` строит `06_fixes.sql` и `07_seed_reference.sql` по enum-ам и константам
   из декомпилированного кода:
   ```bash
   ilspycmd -p -o <src>\NetCity.Common Assemblies\NetCity.Common.dll   # и другие ключевые сборки
   python db_reverse/tools/make_seed.py <src> db_reverse
   ```
4. **Проверка в работе.** Каждый пройденный в интерфейсе сценарий выявлял расхождения. Их причина и исправление
   записываются в генератор, чтобы `rebuild-db.ps1` воспроизводил рабочую БД с нуля.

### Типовые расхождения

Полезно знать, если будете продолжать работу:

- **Угаданный тип или ключ legacy-таблицы.** Например, `NVARCHAR` вместо `INT` или PK без `TERMID`.
- **FK из ORM-маппинга, которого не было в оригинале.** Legacy-SQL пишет `0` или отрицательные значения вместо `NULL`.
- **NOT NULL-свойство ORM при колонке, которую legacy-INSERT не заполняет.** Нужен `DEFAULT`, иначе будет
  `InvalidCastException` или «Переполнение SqlDateTime».
- **Таблица, которую код только читает.** В оригинале это могло быть представление или таблица, заполняемая
  триггером (пример — `MOV_DOCSCLASSES`).
- **Данные, которые приложение создаёт «попутно».** Например, периоды движения создаются вместе с учебным годом;
  если год вставлен скриптом, их нужно досеять.

## Отладка

| Компонент | Где смотреть |
|---|---|
| WebApi / ASP.NET | `WebApi\Logs\log.txt` (cp1251, читать с `FileShare.ReadWrite`) |
| Классический ASP | таблица `USEREVENTS`, колонка `DETAILS2` |
| Служба | `Assemblies\Logs\logYYYYMMDD.txt`, журнал Windows Application |
| Очередь задач | `Assemblies\Logs\QueueProcessorHost.log`, таблица `QUEUEDTASKS` |

- **SQL-ошибка без текста запроса.** Создайте сессию Extended Events на `sqlserver.error_reported` с `ACTION(sqlserver.sql_text)`,
  повторите действие и прочитайте `sys.dm_xe_session_targets`.
- **Проверка запроса из декомпилированного кода.** `SET NOEXEC ON; <запрос>`: неверные колонки выдаются при компиляции.
- **Справочники из `/webapi/references/*` кешируются навсегда.** После их изменения обновите время `WebApi\Web.config`
  и очистите данные сайта в браузере.
- **Старые ASP-страницы требуют токен.** Выполните в консоли браузера `location.href='/asp/...asp?AT=' + strATTok`.
- **Зависшие сессии мастера ввода данных.** `deploy\reset-sessions.ps1`.

## Ограничения

- **Данные не восстанавливаются.** Создаётся пустая система со справочниками.
- **Хранимые процедуры.** Тела существовали только в утерянной БД. Кодом вызываются, но пока отсутствуют:
  - переход учебного года: `COPYSTAFFTONEWYEAR`, `COPYUSERINFOTONEWYEAR`;
  - пользователи и кабинеты: `UPDATEROOM`, `UPDATEFAMILYINFOPARAM`, `DELPARENTFROMSCHOOL`, `UNASSIGNPARENTFROMSTUDENT`;
  - отчёты: `DELETE_SCHOOLREPORTS`, `COPYREPORT`;
  - ресурсы, документы и портфолио: `SCHOOL_DOC_GROUP_REMOVE`, `SCHOOL_RESOURCE_GROUP_*`, `PORTFOLIO_*`.
- **Представления и функции.** Часть из `04_views_functions_procs.sql` — только заглушки: `GET_STUDENTSCLASSES`,
  `STUDENTSCLASSES_ON_DATE`, `TOTALS_AND_LAST_TERM_YEARTOTALS` и др.
- **Read-only legacy-таблицы.** `CSG_CLASSES_TERMS_STUDENTS`, `SGG_CLASSES_TERMS_STUDENTS`, `SG_CLASSES_TERMS`
  в оригинале, вероятно, были представлениями.
- **Придуманные справочники.** Некоторых значений в коде нет, их названия подобраны по смыслу (например, типы классов,
  кроме «Специальное коррекционное обучение»). Такие места отмечены комментариями в `make_seed.py`.
- **Отключённые модули.** Модуль учебных материалов (Firebird `la4.gdb`), КЛАДР и СКУД не восстанавливались.

## Участие

Сообщения об ошибках приветствуются. К ним приложите:
- действие в интерфейсе;
- фрагмент `WebApi\Logs\log.txt` или строку из `USEREVENTS`;
- для SQL-ошибок — текст запроса.

Исправления схемы и справочников вносите в генераторы (`tools/make_seed.py`, `analyze.py`, `Gen.cs`) или в
`04a_functions_impl.sql`, а не только в готовые `.sql`.
